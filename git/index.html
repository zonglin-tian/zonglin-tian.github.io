Git

学以致用

  • 有时提交完才发现漏掉了几个文件没有添加, 或者提交信息写错了. 此时, 可以运行带有 --amend 选项的提交命令来重新提交: git commit --amend
  • 查看提交历史 git log: 提交时间, 提交信息, 提交作者, SHA-1 校验和
    • -p 或 --patch: 显示每次提交引入的差异
    • -n: 限制显示的日志条目数量
    • --stat: 提交的简略统计信息
    • --oneline: 每个提交放在一行显示
    • --graph [--all]: 显示[所有]分支与合并历史
  • 工作树 (Worktree): 在同一个仓库下同时检出多个分支到不同目录, 每个目录都是独立的工作区, 但共享同一个仓库. 既节省磁盘空间, 又能实现多分支并行开发, 告别频繁切换分支的烦恼 ← 主工作树 VS 链接工作树
    • 为特定分支工作树: git worktree add <path> <branch> (当 branch 不存在时, 会自动根据当前 HEAD 新建该分支)
    • 同时创建新分支和工作树: git worktree add -b <new_branch> <path> <based_branch>
    • 查看所有工作树: git worktree list
  • 典型工作树+分支模型:
    1. 紧急修复 + 功能开发并行
      • project: 稳定
      • project-feature-login, feature/login: 开发 login 功能
      • project-feature-pay, feature/pay: 开发 pay 功能
      • project-hotfix-issue-123: 修 bug, issue
    2. 多版本同时维护, 跨分支代码对比调试
      • project: 主开发分支
      • project-v1, release/v1: 旧版本维护
      • project-v2, release/v2: 当前版本维护
    3. 并行构建不同配置
      • project: 开发分支, 代码持续变动
      • project-build, main: 仅用于构建, 不直接编辑

基本概念

  • 工作区 (Working directory): 实际编辑的文件
  • 暂存区 (Stage/Index): git add 后待提交的内容 (相当于 “购物车”)
  • 本地仓库 (Repository): git commit 后生成的历史快照
  • 远程仓库 (Remote): GitHub 上的仓库

帮助

三种等效的方法来获取任何 Git 命令的完整手册页 (manpage):

  • git help <verb>
  • git <verb> --help (-h 获取简洁帮助输出)
  • man git-<verb>

配置

  • 查看配置: git config --list
    • 显示配置项的来源: --show-origin
    • 全局配置: --global
    • 仓库配置: --local
  • 查看某一特定键的值与来源: git config [--show-origin] <key>
  • 配置文件位置:
    • 系统级 (--system): [path]\etc\gitconfig
    • 用户级 (--global): $HOME\.gitconfig
    • 仓库级 (--local): $rep_dir\.git\config
  • 配置用户
    • git config --global user.name "user_name"
    • git config --global user.email "user_mail"
  • 配置代理
    • 配置文件写入
    • 使用 git config --global 终端命令 (更多代理介绍参见系统代理)
      • http: http.proxy "socks5://127.0.0.1:12345"
      • https: https.proxy "http://127.0.0.1:12345"
      • 取消: git config –-global –unset http[s].proxy
  • 换行符 (core.autocrlf automatic carriage-return/line-feed conversion): git config --global core.autocrlf <value>
    • true: 提交时 CRLF → LF, 检出时 LF → CRLF, Windows 常用
    • input: 提交时 CRLF → LF, 检出不转换, Linux 常用
    • false: 不转换, 原样提交, 特殊场景
    • 查看文件换行符:
      • 验证规则: git check-attr -a -- <file>
      • 本地端: git ls-files --eol | head
      • 服务端: file <script> (i/: 仓库, w/ 工作区)
    • 使用全局 .gitattributes 统一规范: git config --global core.attributesfile ~/.gitattributes
    • 让已有文件重新归一化: git add --renormalize . && git commint -m "Normalize line endings" → git checkout-index -a -f (更新工作区)
  • 全局忽略的文件列表: git config --global core.excludesFile $HOME/.gitignore
    • 验证是否生效: git check-ignore -v <file>
    • 查看哪些文件被 ignore: git status --ignored

常用命令

入门

  • 创建新仓库: git init
  • clone 特定版本的仓库: git clone --branch <version> <url>
  • 检查已添加的内容: git status

准备提交

  • 添加所有未跟踪的文件和未暂存的更改: git add .
  • 添加未跟踪的文件或未暂存的更改: git add <file>
  • 移动文件: git mv <old> <new>
  • 删除文件: git rm <file>
  • 告诉 Git 忘记某个文件但不删除它 (文件保留在磁盘, 但是不让 Git 继续跟踪): git rm --cached <file>
  • 取消所有暂存: git reset 或 git restore --staged .
  • 取消暂存单个文件: git reset <file> 或 git restore --staged <file>

进行提交

  • 打开文本编辑器编写提交信息: git commit
  • 附带提交信息提交: git commit -m 'message'
  • 提交所有未暂存的更改: git commit -am 'message'

在分支间切换

  • 切换到上一个分支: git switch -
  • 切换分支: git switch <name> 或 git checkout <name>
  • 创建并切换到分支: git switch -c <name> 或 git checkout -b <name>
  • 列出分支: git branch
  • 删除分支: git branch -d <name>
  • 强制删除分支: git branch -D <name>

工作树

  • 为特定分支创建工作树: git worktree add <path> <branch> (当 branch 不存在时, 会自动根据当前 HEAD 新建该分支)
  • 同时创建新分支和工作树: git worktree add -b <new_branch> <path> <based_branch>
  • 创建裸工作树 (不检出文件, 仅用于构建): git worktree add --no-checkout <path> <based_branch>
  • 查看所有工作树: git worktree list
  • 删除工作树: git worktree remove <path>
  • 清理失效工作树: git worktree prune

比较更改

  • 比较所有已暂存和未暂存的更改: git diff HEAD
  • 仅比较已暂存的更改: git diff --staged
  • 仅比较未暂存的更改: git diff

比较提交

  • 显示某次提交与其父提交之间的差异: git show <commit>
  • 比较两次提交: git diff <commit> <commit>
  • 比较某个文件自某次提交以来的差异: git diff <commit> <file>
  • 显示差异摘要: git diff <commit> --stat 或 git show <commit> --stat

代码考古

  • 查看分支历史
  • 显示修改过某个文件的所有提交: git log <file>
